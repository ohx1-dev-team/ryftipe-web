# Ryftipe 0.31.0 — Accountless local-first browser

## Product decision
Ryftipe has no user accounts, registration, login, shared password gate, database, or cloud sync. The browser opens directly to its homepage.

## Changes
- Removed the password login UI and client-side authentication request.
- Removed the optional shared-password environment variable, token map, authentication endpoints, and auth checks around RTE resources, diagnostics, and the Chromium WebSocket.
- Preserved same-origin validation for WebSocket upgrades and the existing maximum concurrent session limit.
- Kept browser preferences, bookmarks, and history in browser-local storage.
- Updated the visible version to 0.31.0 and clarified local-only storage in Settings and About.

## Data persistence
Browser-local storage is independent of the Render deployment filesystem. A normal app deployment at the same origin does not clear a user's localStorage. Data is still specific to the browser profile and origin; clearing site data, using a different origin, or losing the browser profile can remove it. There is no cross-device sync or server-side backup.

## Security and deployment
There is no application-level authentication. Anyone who can reach a public deployment can use it, up to the configured session limit. Public deployments must be protected by an appropriate hosting/network access-control layer before being exposed to untrusted users. Existing URL filtering remains best-effort and is not a substitute for network egress controls.

## Validation
- Static regression tests verify that the login UI, authentication endpoints, password-token checks, and password environment variable are absent.
- Static regression tests verify direct browser startup and localStorage-backed user data.
- Run `npm test` in the repository environment.
- Render deployment and live website behavior must be checked separately; this change does not claim a successful deployment.
