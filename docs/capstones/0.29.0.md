# Ryftipe 0.29.0 — larger RTE application pages

## Goal
Improve complex multi-script sites in Ryftipe's own RTE without switching to Chromium.

## Changes
- Raise the bounded script-selection and execution ceiling from 40 to 80 entries. This directly addresses pages whose HTML declares more than 40 scripts, which were previously omitted before execution.
- Raise the isolated DOM snapshot node ceiling from 1,800 to 12,000 so dynamic application interfaces are less likely to be truncated during mutation snapshots.
- Keep existing per-script and aggregate byte budgets, URL validation, read-only network policy, and sandbox separation unchanged.
- Extend the script-cap regression test to cover 100 declared entries and verify the 80-entry bound.

## Compatibility limits
This is a targeted capacity improvement, not a claim that RTE is fully browser-compatible. Sites can still require unsupported browser APIs, write requests, service workers, WebSockets, DRM, WebGL, or other features. TopEaglerServers.com must be tested in the deployed RTE before calling it fixed. Chromium fallback is not part of the intended solution.

## Validation
Run `npm test` and test `https://topeaglerservers.com` in the deployed RTE. Record script counts, runtime errors, page interactions, and whether the site's main content loads. Do not infer site compatibility from script execution counts alone.
