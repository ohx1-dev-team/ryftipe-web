# Ryftipe 0.28.0 — JavaScript and cross-origin compatibility capstone

## Goal
Improve the RTE JavaScript path for modern multi-origin websites without switching the default engine to Chromium.

## Changes
- Allow the isolated RTE runtime's read-only fetch/XHR bridge to request public cross-origin HTTP(S) resources. Every upstream request and redirect still passes the server's DNS/IP validation; credentials and non-GET methods remain blocked.
- Permit bounded ES module graphs to resolve public cross-origin HTTPS dependencies, while continuing to reject bare imports, dynamic imports, credentials, and non-HTTP(S) protocols.
- Raise the bounded script selection ceiling from 20 to 40 entries and the aggregate module/script budget from 2.4 MB to 6 MB.
- Preserve SVG and canvas elements in parsed snapshots; create SVG nodes in the SVG namespace and preserve common case-sensitive SVG attributes. Keep active embedded browsing contexts removed.
- Add focused tests for cross-origin request policy, module graph resolution, script limits, and SVG parsing.

## Compatibility limits
This is an RTE compatibility improvement, not a claim of full browser conformance. The bridge remains read-only and does not forward cookies or authorization. Sites requiring POST APIs, service workers, WebSockets, WebRTC, DRM/EME, protected media, or browser-specific APIs can still fail. YouTube playback is not considered fixed until the live playback probe actually passes in the deployed RTE.

## Validation
Run npm test and npm run test:youtube. The YouTube probe is an integration test and may fail when the site requires unsupported APIs or network access. Do not treat fixture tests as proof of YouTube compatibility.
