# Ryftipe 0.30.0 — RTE cross-origin network bridge and version sync

## Objective
Make the existing validated cross-origin read-only request bridge usable by website JavaScript inside the isolated RTE sandbox, and ensure the visible browser version matches the release.

## Root cause
The shared RTE policy already accepted validated cross-origin HTTP(S) GET URLs, and the server bridge validates public destinations and redirects. However, the isolated sandbox's `window.fetch` shim still rejected requests whose origin differed from the current page. This prevented both fetch-based and XHR-based site code from reaching the parent bridge.

## Changes
- Add a sandbox URL resolver that accepts HTTP(S) URLs across origins while rejecting credentials, unsupported schemes, and oversized URLs.
- Route the resolved URL through the existing parent runtime bridge. Keep GET-only behavior; the parent policy and server-side public-IP/redirect validation remain authoritative.
- Keep XHR backed by the same fetch bridge, so cross-origin XHR GETs follow the same policy.
- Update the RTE diagnostic rejection message to describe the actual validated public HTTP(S) GET policy.
- Bump package version to 0.30.0.
- Update the top-right browser version label and About page version to 0.30.0.
- Add regression tests for cross-origin URL resolution, unsafe URL rejection, and shared fetch/XHR bridge wiring.

## Security boundaries
No cookies, authorization headers, credentials, or non-GET methods are forwarded. The sandbox is not allowed to bypass the parent runtime or server request validation. The server-side destination and redirect checks remain required for SSRF protection.

## Compatibility limits
This fixes a concrete sandbox/network-policy contradiction. It does not prove TopEaglersServers.com, YouTube, or arbitrary websites are fully compatible. Websites may still depend on POST APIs, WebSockets, workers, service workers, browser APIs, WebGL, media pipelines, or other capabilities not implemented by RTE. Chromium fallback is not the intended solution.

## Validation plan
Run `npm test` and verify the deployment on TopEaglersServers.com using RTE only. Confirm that cross-origin GET requests reach the validated bridge, page content loads, and important interactions work. Do not call the site fixed until the deployed test passes.
