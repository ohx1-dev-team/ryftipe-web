# Ryftipe 0.27.0 — RTE HTML tree construction

## Capstone focus

This capstone improves Ryftipe's own RTE engine. It does not promote Chromium or add a Chromium runtime dependency.

## Changes

- Replaces the previous broad tag-token regex loop with a quote-aware scanner that finds tag boundaries without treating `>` inside quoted attributes as the end of a tag.
- Improves attribute parsing for boolean, quoted, unquoted, duplicate, and entity-containing values.
- Preserves text whitespace instead of collapsing every run of whitespace, which is important for `pre` and source-formatted content.
- Adds common HTML implied-end-tag handling for paragraphs, list items, definition terms, options, table rows/cells, anchors, and forms.
- Handles raw-text script/style content without interpreting markup-looking strings as actual elements. Script/style contents remain excluded from the rendered DOM; script extraction stays in its dedicated path.
- Handles textarea/title RCDATA text and entity decoding.
- Skips embedded browsing contexts and their descendants (iframe/object/SVG/canvas) rather than accidentally promoting their fallback markup into the parent document.
- Bounds parser input, tree depth, element count, text-node size, and per-parent child count.
- Adds focused regression tests for parser behavior and stylesheet link token matching.

## Compatibility note

This is a foundational parser improvement, not a claim of full WHATWG HTML conformance. It does not implement a complete browser DOM, CSS layout engine, or the modern Web APIs needed by complex applications. YouTube, AO3, Discord, and TopEaglerServers still require real-world compatibility testing in RTE before being described as supported.
